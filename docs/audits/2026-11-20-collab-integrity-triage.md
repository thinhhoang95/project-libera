# Shared notebook integrity: triage and fix plan (2026-11-20)

Source: a static Codex review (gpt-6.2-sol, xhigh) of `main` at `b3f6269`. It covers shared notebooks: in-app moves through the collaboration host, moves made by a collaborator, outside moves in the working folder, the host's SQLite and the server's sync, deadlocks, Check Notebook, Try to fix, Acknowledge and lifecycle transitions. It has 74 findings (S1–S74), reproduced verbatim in [2026-11-20-codex-collab-integrity-review.md](2026-11-20-codex-collab-integrity-review.md). This round follows the local-notebook round ([2026-11-20-move-integrity-triage.md](2026-11-20-move-integrity-triage.md)).

## Rules for the round

- Every finding is treated as real until the fixing agent shows otherwise from the code.
- **Check Notebook is the oracle.** Every in-app move, fix or automatic upkeep step, in a shared notebook too, must leave a state whose findings the verifier agrees with, unless the user acknowledged them. No module keeps a rule of its own where the verifier has one. Tests assert `assertNotebookSound` (or the verifier's findings) after the operation where the harness allows it.
- **Try to fix stays name-based.** Do not use fingerprints, stamps, retention or merge layers. The collaboration layer's own identities (manifest file IDs, document IDs, blob SHA-256) are the sync design and may be used to bind operations and records.
- **Shared text changes only through the host** (`writeSharedText`, `applyEdits`, the host's file ops). Never write a shared file's text on disk directly.
- Migrations keep refusing shared notebooks.
- **Destructive steps fail closed.** If a check cannot establish that something is stale, free, unique or owned, the step is refused or held, and the report says so.
- **Once the host has committed a change, it cannot be taken back.** Every follow-up step runs, and anything that stays behind is reported as `SharedOperationUnfinishedError` (`src/lib/collab/shared-outcomes.ts`), which carries the committed mapping.
- **No battery drain** (added by the user during the round). No new polling loops or fixed-interval timers: prefer existing events and operation completion. A timer that cannot be avoided reschedules itself, is scaled by the host's battery scale, is unref'd and stops when nothing is pending. Retries use capped backoff that resets only on real progress. No full tree fetches, walks, scans or whole-file hashes where the affected paths suffice. Recorded hashes are reused, and an online-only placeholder is never hydrated just to check it. Identical writes are skipped. Each package reports what it adds and how it is bounded (background: [2026-11-19-sync-onedrive-battery-audit.md](2026-11-19-sync-onedrive-battery-audit.md), findings 36–43).
- Tests: run the package's own test files once, then `npx tsc --noEmit -p .` once (and `-p server` when server code changed), and eslint on the changed files once. No full suites, fuzz or soak loops.

## Decisions taken in triage

- **Records follow every manifest move, durably (S4, S31, S35).** The host keeps a durable per-project log of manifest transitions, keyed by file ID: moves and removals, local or remote. Next applies the log to the records it keeps on this computer, idempotently and with ownership checks, then acknowledges it. The shared wrappers apply their own transition at once, so the response reports the outcome. The log makes sure a crash, a lost response or a remote move still gets applied later.
- **Links follow shared moves (S21, S22).** This reverses "a move inside a shared notebook rewrites nothing". Rewrites go through the host with a text precondition. Anything not rewritten is reported, as for a local move.
- **Try to fix and Acknowledge on a shared notebook (S66, S67).** The report says which actions are possible. Try to fix may pair *this computer's* records (stars, tags, local sidecars, reviews, attachments) under the name rule, but only to a file the host's manifest lists at commit, and only when the old path is gone from the manifest. Acknowledge may remove local-only records under the same check. Anything the host owns stays refused.
- **Check Notebook asks the host (S63, S64).** On a shared notebook it compares the disk with a read-only manifest view and with the live PDF document. When the host cannot answer, those checks are reported as partial.
- **Ambiguous outside renames are not guessed (S40, S41, S44).** When the evidence is uncertain (bytes differ, the absence is uncertain, the late-copy evidence is missing), the host holds the case for the user through its existing reconciliation, and both inputs are kept.

S18 (single operations and the batch) and S16 (host and Next) were shared by two packages. S8 was mostly covered by B1's per-file transitions; B2 closed the rest.

Found by the final test pass and fixed by the owning package: the scanner's bookkeeping did not exist in projects built without field initializers (H2); the transition-log tables collided with a re-migrated legacy database (B1, now created only if missing); a removed member's binaries were fetched only from the takedown recovery route (LC, now cache, then the normal download, then recovery); reviews created after sharing were skipped by the comment transfer (LC, now by stored path when the share-time map does not name them); the action-time identity check refused documents whose working copy trails the live text, files not on disk yet and invalid paths before validation (T1); a revoked member's final local PDF export was skipped when the PDF hub closed first (PL, `writeCurrentCopy`).

Found while merging and fixed here: blob collection dropped the orphan row of a blob held only for a takedown's recovery, so it would never have been collected after the hold (`server/src/blobs/gc.ts`); LC's server migration was renumbered 013 after SV's 012; the verify, repair and cleanup routes apply pending record moves before they plan (`settleSharedRecordsBeforeCheck`), so `verifyNotebook` stays read-only.

Battery: no package added a polling loop or a fixed-interval timer. New timers are one per call and cleared (host-call and read deadlines), or self-rescheduling and stopped when idle (the lifecycle reservation's renewal while held; the blocked-command backoff, now scaled on battery). Drains of the transition log run on events and cost one indexed host query when nothing is pending; scan fairness counts in scan passes; identity checks read only the file acted on.

### Tests

Run once on the merged branch, then the files that failed once more after their fixes.

- Server suite (`server/test`, PGlite): 232 tests; the two failures were this round's intended contracts (the recovery report and hold) plus the blob-collection bug above; after the fixes the affected files pass (19/19).
- Editor, the 82 files that import this round's storage and collab modules: 819 tests. Failing on `main` as well, so not this round: `audit-1119-local-writes` "a folder rename that fails part-way is rolled back completely", `references-moves` "the files route returns the references result with the moved file", `tree-metadata` "metadata by path matches the tree's node", and two `global-search-triggers` tests cancelled by the runner. `notebook-repair` test 71 failed once under full parallel load (a `.bib` tether from test 68 leaked into it) and passes alone (21/21).
- Collab suite (`npm run test:collab`): 857 + 42 timed tests. Failing on `main` as well: `albums-host` "when access ends, the member keeps the photos they added", `audit-1119-fs-exclusive` "movePathExclusive refuses a folder onto an existing folder", `audit-1119-writer-pass` "finding 29: a move that cannot stage keeps the old path until it can" (main fails two of its subtests; this branch one). Every other failure was a regression of this round, fixed by its package and re-run: the 13 files 89/90 then the scanner files 23/23; `pdf-live-host` passes in full with the final-export fix (run on a quiet machine). `p3b-agentic-review` failed once under load and passes alone.
- `npx tsc --noEmit -p .` and `-p server/tsconfig.json`: clean.

Not run: the whole editor suite (its 384 files; the 82 above are the ones this round's modules reach), the fuzz, soak and load suites, and the app itself (no in-app session on a shared notebook was driven this round).
