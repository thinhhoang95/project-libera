# Notebook check

**Notebook actions → Check Notebook…** checks a notebook against the disk and lists what is not sound, with what would set each finding right. The check only reads: nothing is repaired, moved or rewritten (that is **Try to fix**, below, and only on confirmation), and it does not load the library tree (whose upkeep prunes sidecars and writes indexes). It runs only when asked, shows which check it is on, and can be stopped.

Code: `src/lib/storage/integrity.ts` (`verifyNotebook`, `checkNothingLeftAt`), `src/app/api/notebooks/verify/route.ts`, `src/components/libera/notebook-integrity-dialog.tsx`. Tests: `scripts/editor/notebook-integrity.test.ts`, `scripts/editor/notebook-operations-integrity.test.ts`.

## One common point

The check owns no knowledge of its own. Each kind of state is asked of the module that owns it, and checked against the disk:

| Check | Asks | Finding |
|---|---|---|
| Notebook settings | `notebookMetadataPath` | settings file missing (info) or unreadable (error) |
| Side files | `listSidecars` (a folder is a file's ink folder only if it directly holds a file the ink reader accepts; stray files beside it make none), `findOrphanedSidecars`, each kind's `inspect` (sidecars.ts, from the owner: `inspectPdfSidecar`, `inspectImageSidecar`, `inspectPdfTextCache`, `inspectAudioPeaksCache`, `inspectInkFolder`, and the outline, definitions and transcript parsers), `matchByIdentity` and `readOrphans` (pdf-sidecars.ts) | a saved side file its owner rejects, or ink files the reader leaves out (error); records its reader silently drops, which the next save loses: annotations, comments, strokes, outline entries, definitions, transcript segments (warning); side files of a file that is gone (warning), or that belong to a file moved outside the app, which they follow the next time the notebook is opened (info); a side file made for another version of its file, by size (info; for ink, only the page files whose recorded size differs, so pages drawn on the current version are not named; annotations and comments are only reported, never offered for removal); PDF text caches and waveforms out of date, one line per kind (info); ink of a page or block the file doesn't have, side files set aside for files that may come back (info) |
| Note images and Python code | `unreferencedMarkdownAssets` (markdown-assets.ts) | Python code of a note that is gone (warning); images no note shows (info) |
| Images in notes | `markdownImageTargets` | an embedded image, Markdown or HTML `<img>`, that is missing (error) |
| Links in notes | `linkCandidates`, `resolveLinkTargetWith` (library-links.ts), `markdownHeadingAnchors`, `savedAnnotationIds` (annotations.ts), `hasUnreadableLinkPosition` | a link (inline or reference-style) that finds no file, resolved as the editor resolves it; a heading, in the note or another, that is not there (HTML anchors count); a link to an annotation that is gone; a moment past the end of a recording (by its transcript's or waveform's length); a saved place that can't be read, a ```chart block whose data file (`.csv`/`.tsv`, from the note's folder) is missing (all warnings) |
| LaTeX | `latexDependencies` (latex/dependencies.ts) | an `\input`/`\include`, `\includepdf`, `\lstinputlisting`, figure or bibliography that is not found from the main file's folder (error). A name is tried as written, then with each extension TeX adds (`plot.v2` → `plot.v2.pdf`, `chap.v2` → `chap.v2.tex`). A name that needs a macro (`#1`, `\figdir/a`) is not resolved: the check says how many references it could not check (partly checked, no finding). `\usepackage` and `\documentclass` are not checked |
| Records | `inspectWorkspaceMetadata` (workspace-metadata.ts, which says when the file is damaged instead of reading it as empty), `inspectReviewKeys`, `inspectMissingReviewDocuments` (review-files.ts, lock-free), `listReviewEntryPaths`, `listRunFiles` | stars and tags of missing files, pending agent reviews of missing files (warning); review comments and undo history kept for missing files (info); a damaged stars-and-tags file (error); review comments whose document file is not on this computer, not synced yet or lost (warning, never offered for removal); unreadable review records (warning or error) |
| References | `inspectReferenceLibrary` (the app's own parser, without setting a damaged library aside), `readTetherTarget` | a reference attached to a missing file, a missing tethered `.bib` or unreadable tether settings (warning); a tether to a file outside the library whose folder is missing too is reported as possibly on a drive that is not connected, and is never offered for removal; a library the app can't read (error) |
| Indexes | `readLinkIndex` (notebook-links.ts), `readCitationIndex` (reference-citations.ts), `planBibMirror` (bib-mirror.ts, what `writeBibMirror` would do), `readIndexedLibraryPaths` (search/database.ts) | link and citation index entries whose content hash no longer matches the note (the citation index's LaTeX entries are hashed too, and a note with invalid UTF-8 is compared by its raw bytes, as the indexes hash them), notes not indexed yet, entries of files that are gone; a `.bib` mirror out of date, not written, or protected because it was edited; Global Search rows of files no longer in the notebook (all info, aggregated) |
| Migrations | `listInterruptedMigrations`, `listUnreadableMigrations` | an unfinished migration involving the notebook (error); an unreadable journal, a prepared copy left behind (warning) |

The notebook is walked once and its notes read once per check; files are checked for existence once each, and the side files are listed once. Existence is exact, as the app matches paths: each name on the way must be in its folder's listing (`readdir`, once per folder), so `Paper.pdf` is missing when the file is `paper.pdf` and a name that differs only in Unicode normalization is missing too, even where the file system would open it (stars, tags, reviews, attachments and links are matched by string against the tree, so a case-only rename in Finder loses them). Image embeds and LaTeX files are looked up on the disk as the viewer and TeX do, so those two keep the file system's own matching. Side files are compared with their file by size only (a stat), never by hashing the PDFs and recordings: a same-size change is left to the owner when the file is opened. Files are hashed only to match side files of a missing file, and only those of the size it recorded. Index entries are compared with hashes of the notes already read. Each check runs on its own: one that can't run is reported as such, and one that could only partly run (very large notebooks, unreadable notes, a folder or file it had no permission to read) says so. A path that could not be checked is never reported as missing. When any check is partial, the dialog says **Partly checked** instead of "No problems found".

## Try to fix: files moved outside the app

Files moved or renamed into another folder in Finder (or by a sync client) leave their records at the old path. When the check has findings that can come from that (side files, a note's Python code, records, references), the dialog offers **Try to fix…** (`src/lib/storage/repair.ts`, `src/app/api/notebooks/repair/route.ts`).

- **Plan (reads only).** The paths that records are kept for (side files, Python code, stars and tags, review comments, reference attachments in any library, the tethered `.bib`) and that are surely gone are matched to the notebook's files **by name alone**. A pair is made when exactly one missing path has that name and exactly one file has it, and that file has no records of the same kind of its own (stars and attachments don't count). An empty review, the one opening a note makes, is not the file's own: opening a moved note before the fix doesn't keep its comments from following it. Everything else is listed as left alone, with why: no file of that name, several files of that name, several missing files of that name, or the only one has records of its own. Caches never make a match; they follow a matched file.
- **Names.** A name is compared under Unicode normalization (NFC) and case-folding, so a name a sync client returns decomposed (`Bài giảng.pdf`) and a case-only rename (`Paper.pdf` to `paper.pdf`) are found; files that fold to one name are "several". A path is also missing when its exact name is not in its folder's listing, so a case-insensitive disk that answers "exists" for the old spelling does not hide the rename.
- **The archive** (`_archive`) is searched: a file moved there in Finder is a candidate, and a same-name file there counts toward "several".
- **Side files set aside.** The tree's upkeep sets side files aside (`.libera/orphaned-sidecars/`) 30 s after their file goes missing. Each set-aside record (annotations, outline, definitions, ink) is a record of its `originalPath` and is paired by the same rule. Ink records no identity of its file, so this is its only way back. A destination that already has that kind of side file makes the pair "own", as for live side files.
- **Not planned at all** when a folder of the notebook could not be listed (permissions, a drive offline) or the notebook has too many files: a name can't be known to be the only one. A folder that raced away is not one of these.
- **Warning.** There is no fingerprint: a different file with the same name gets the records. The dialog says so and shows every pair before anything is written.
- **Apply (on confirmation).** The plan is made again and refused if it differs from the one shown (a token). Side files and the Python code move as in an in-app move, but never over what the file found already has (the destination is created exclusively, so a side file the app saves there meanwhile is kept and the old one stays, and is reported; a pair of which nothing moved for that reason is not listed as moved, and a pair that fails stops only itself; set-aside side files are written exclusively too, then their record is removed, and the next plan only pairs what is left); an open note whose review was replaced reloads it (`REVIEWS_MOVED_EVENT`), and a review client whose review id is gone loads the path's review instead; then review comments (an empty review at the new path gives way; one that gained comments since keeps them, and the moved review stays where it was), stars and tags, reference attachments and the tethered `.bib` follow in one write per store (the migration's batch helpers), and Global Search is told. Markdown links are not rewritten, as for every move in the app (`docs/features/related-notebooks.md`); the check run after the fix still lists them. Not for shared notebooks, nor while a migration involving the notebook is unfinished.

A recording's transcript is kept when the recording is missing (the tree's upkeep, `pruneAudioSidecars`, drops only its waveform), so a recording moved in Finder gets it back. Tests: `scripts/editor/notebook-repair.test.ts`.

## Acknowledge: removing what is stale

After Try to fix has found what it can, **Acknowledge…** removes what the check still reports as stale, so that checking again lists only what needs you (`src/lib/storage/cleanup.ts`, `src/app/api/notebooks/cleanup/route.ts`). The check marks each finding it can clear with `clear` (the actions that remove it), so the two always agree on what is stale:

- what is left of files that are gone: their side files, side files set aside in case they come back, a note's Python code, stars, tags, review comments, the agent's changes waiting for review, reference attachments, a tether to a missing `.bib`;
- side files saved for another version of a file that is still there (definitions, outlines, transcripts, and ink, which goes with them), ink files of pages the file doesn't have, images no note shows;
- out-of-date caches, the citation index and the `.bib` mirror.

Never stale, by the same name rule as Try to fix: an image no note shows whose file name a note's missing embed has (probably that embed's image, left behind when a folder moved), Python code named like a note that has no code of its own, side files of a file that can't be checked (no permission, a drive offline), and side files set aside for a file that is back (same bytes, or back under its old path), ink included; these stay listed, with what to do.

Also left out, and counted as remaining (the plan says why in `notes`): records of a path that Try to fix could not pair only because several files have its file's name (`several`, `shared-name`, `own`: after a folder rename in Finder, repeated names like `notes.md` may belong to one of them), set-aside side files of such a path included; and everything a check found that ran only in part (`incomplete` or `failed`), since a partly run check can't tell what is stale (its protection of set-aside files whose file came back may not have run). Both plan and apply filter the same way, so the token agrees. Records of a file moved to *another notebook* in Finder are not protected: names are not matched across notebooks. The refusal while Try to fix can still move records names the pairs.

Some of this is what people made. The dialog lists every item with what removing it costs, marks what is deleted for good (annotations, ink, comments, transcripts, code, images, pending agent changes), and when there is any, the remove button waits for **I understand these are deleted for good**. Acknowledge is refused while Try to fix can still give a moved file its records back, so they are never deleted instead of moved. Applying runs the check again and is refused if what it would remove changed (a token: each action names exactly what it removes, an attachment by its library and reference, the tether by its target). Right before each removal, the file whose absence made it stale is checked to be still gone, and nothing is deleted whose folder, once links and junctions are followed, is outside the notebook or its system folder. A review is deleted for its exact path, an attachment from its one reference; a removal that fails is reported, and its finding stays. It then refreshes the tree, whose upkeep moves side files to files found again and brings the link index up to date, before checking again. Not stale, and left listed: broken links, missing images and LaTeX files, unreadable or damaged files, records a reader drops, agent undo history, unfinished migrations and the settings file. Not for shared notebooks. Tests: `scripts/editor/notebook-cleanup.test.ts`.

## Moving files in the app

Moving, renaming or archiving a file (`moveFileToDirectory`, `moveFile`, `archiveFile`, and the folder renames and archives in `src/lib/storage/files.ts`) keeps everything that points at its path pointing at it, so a check afterwards finds nothing at the old one:

- **Pending agent reviews** are written at the new path before the file moves and removed from the old one after (`withMovedReview`, `withMovedReviewsUnder` for a folder), so the review is never only at a path whose file is missing. A note moved to another notebook gets its image rewrites, and its cited-key rewrites once `copyCitedReferences` has run, applied to the review's baseline.
- **Undo history** follows through `recordMovedRunFiles` (`recordMovedRunFolder` for a folder), with the same rewrites and the file's hash before and after them.
- **Leftover records at the destination** refuse the move (409, naming what is kept and pointing here): side files other than caches, review comments, pending agent changes, a star or tags, a reference attachment, kept for a file deleted outside the app. They would be destroyed or handed to the moving file. Caches and an empty review (the one opening a note makes, which the moving file's review replaces) don't count. Check Notebook, then Try to fix or Acknowledge, clears them.
- **Drag and drop to another notebook** opens the migration dialog like the Move menu does (`moveFileToFolder`).

Tests: `scripts/editor/notebook-move-integrity.test.ts`.

## Bounds, progress and stopping

A check runs under limits (`DEFAULT_INTEGRITY_LIMITS`: 20,000 entries, 64 MB read, 30 s, 10,000 findings); reaching one makes the checks it cut short partial, saying which limit. The report carries what the check cost (`statistics`) and its `completeness`. With `?stream=1` the route sends newline-delimited JSON: one `progress` line as each check starts, then the `report` (or an `error`). The dialog shows the check it is on and a **Stop** button; stopping, closing the dialog or the request going away aborts the check between reads.

## Read only

Read-only means no maintenance-capable path is used: not the tree load, not the review store's migrating reader, not the reference library's quarantine, not the readers that upgrade older annotation or ink layouts. Finding where a linked folder is reads its state without its upgrades: `verifyNotebook` runs under `withReadOnlyStorage` (paths.ts), under which `readDirectoryModeState` (electron/directory-mode.cjs) neither rewrites an older state file nor writes a folder's identity marker nor records its location. The search index is opened read-only, and only when that creates nothing (a WAL index needs its shared-memory file to exist already); otherwise it is skipped.

Two tests hold this: one snapshots the whole data folder before and after a check; the other replaces every writing call of `fs` and `fs/promises` (and opening for writing) while checking a notebook with every kind of side file, indexes, a mirror and a linked folder in an older state file without its marker, and fails on any call.

## As a test oracle

`scripts/editor/notebook-test-helpers.ts` exports `assertNotebookSound(notebook)`, which runs this check and fails on any error or warning not explicitly expected. The migration tests assert it after every scenario, and `notebook-operations-integrity.test.ts` runs the everyday file operations (move, rename, archive, copy, delete, folder operations, moves between notebooks) on a notebook seeded with every kind of side file, a star, tags and a reference attachment, asserting each leaves both notebooks sound, notes included (except the link and citation indexes' lag, which the app's next tree load clears and the sweep deliberately never runs). It found that a note that stays and shows a moving image by its library address breaks without warning; the migration review now warns about it.

The migration's final check uses `checkNothingLeftAt` from the same module, so "nothing was left behind" means the same thing in both places. The migration review reuses the same link and LaTeX helpers.

## Not checked

- Shared notebooks are checked as they are on this computer, not against the collaboration host, which keeps their files in step.
- A side file is compared with its file by size; a change that keeps the size is found by its owner when the file is opened.
- Links into other notebooks and LaTeX paths outside the notebook are not judged; a link's line in a text file is not checked.
- LaTeX names that need a macro are counted, not resolved, and `\usepackage` and `\documentclass` names are not checked.
- A ```chart block's data file is checked; ```html live blocks and ```mermaid diagrams are not: a live block runs in a sandboxed frame that can't read notebook files (only https or data: URLs load), and Mermaid runs in strict mode with no file references.
- Global Search is skipped when its index can't be opened without creating files (no one has it open).
